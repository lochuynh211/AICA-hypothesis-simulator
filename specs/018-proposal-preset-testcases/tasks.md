## Dependencies & Execution Order

- **Phase 1 (Setup)** → **Phase 2 (Foundational)** must complete before any user story.
- **Retune (T004–T007)** is a scoring-model change: it must land before US3's preset-expectation tuning (T036) and before US2 pair tuning (T031), since preset `top_fit_min`/top-track expectations are measured against post-retune scores. It is placed in Foundational for exactly this reason.
- **US1 (P3 phase)** depends only on Foundational → the MVP.
- **US2** depends on Foundational + the generator (T017) + the harness skeleton (shares `test_presets_expectations.py` with US3).
- **US3** depends on Foundational + all presets authored (US1 T019 + US2 T028) to assert the full catalog; its golden test (T035) depends on the generator (T017).
- **US4** display (T037–T040) depends only on Foundational; the retune half already landed in Phase 2.
- **Polish** last.

## Implementation Strategy
- **MVP = Phase 1 + Phase 2 + Phase 3 (US1)**: a working, provenance-tracked, self-explaining preset selector on post-retune scores. Ship-able increment.
- Then **US2** (contrast pairs) and **US3** (verification guarantee) — the persuasive demo + the trust gate.
- Then **US4** (fit-band display) polish.
- Presets are tuned via the author-specs + regenerate loop, with the US3 harness as the objective green/red signal.
