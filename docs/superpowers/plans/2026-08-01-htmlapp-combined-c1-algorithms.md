# HTMLApp Combined Export — C1: Algorithm Ports — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring all four htmlapp algorithm ports level with their current Python sources, prove each against freshly-captured goldens, and re-enable the three parity tests C0 pinned.

**Architecture:** Each algorithm is a `builtin_js_module` TS file under `src/data/packages/builtin/`, dispatched by package id through `BUILTIN_EVALUATORS`. Its manifest (parameters, hyperparameters, defaults) arrives from the C0 data seam — only executable logic lives in `src/`. Verification is a golden fixture per algorithm, captured by importing the real Python `evaluate()` directly, replayed by a TS conformance test.

**Tech Stack:** TypeScript 5.8, Vitest 1.6, Python 3.12 (stdlib + the repo's `app/api` modules) for capture. No new dependencies.

## Global Constraints

- **No new runtime or dev dependencies.** (See the `httpx2` supply-chain incident.)
- **No changes under `app/frontend/` or `app/api/`.** The Python is the reference; it is never edited to make a port agree.
- **No changes under `src/components/**`** — synced from `app/frontend`.
- **The Python is the behaviour of record.** Where TS and Python disagree, the TS is wrong. If you believe the Python is wrong, stop and report — do not "fix" it in the port.
- Manifests, parameters and hyperparameters are **data** (from the C0 registry); only executable logic is source.
- Capture runs offline: `PYTHONPATH=app/api python htmlapp/frontend/scripts/gen/capture_all.py` from the repo root. No docker, no uvicorn, no `uv`.
- Run all npm commands from `htmlapp/frontend/`. Verify with `npm test` and `npm run typecheck`.
- **The five named Python↔JS divergence hazards** (from the ADR) apply to every port in this slice and must be actively checked, not assumed:
  1. Python `round()` is banker's rounding; JS `Math.round()` is half-up → use an explicit `roundHalfEven` helper wherever Python `round()` appears.
  2. `sorted()` on tuples compares lexicographically → explicit tuple comparators, never a bare `.sort()`.
  3. Python `//` and `%` floor toward −∞; JS truncates toward zero → negative operands diverge.
  4. Dict merge/iteration order must be preserved where it feeds ordered output.
  5. Float→string formatting differs → compare parsed numbers, never serialized JSON.

## Self-Review

**Spec coverage.** Against the ADR's C1 row: re-enable the three pinned tests (Task 2 Step 5), refresh `aica_transparent_hybrid_trigger_v1` (Task 3) and `nri_fatigue_score_v1` (Task 2), add `aica_transparent_service_selector_v1` (Task 4) and `aica_transparent_content_selector_v1` (Task 5), layer-3 conformance goldens (all four tasks), and the `PINNED-TO-C1` grep gate (Task 6 Step 2). Covered.

**One addition the ADR did not anticipate:** Task 1, repairing `capture_all.py`. It is broken by a retired algorithm type *and* by C0's deletion of the file it read. No golden in this slice can be regenerated until it runs, so it must come first.

**Deliberate deviation from the usual plan format:** the port tasks do not embed the target code. For a port, the authoritative source *is* the Python file, and transcribing ~3,600 lines into the plan would create a second copy to drift. Each task instead names the exact source file, the exact target, the enumerated gap as a required report artefact, the golden that judges it, and the hazards to check. The test-first discipline is preserved: every port task starts by proving the current port fails against a freshly-captured golden.

**Type consistency.** `evaluate` is the exported name in all four ports; `BUILTIN_EVALUATORS` keys by package id; `UNPORTED_BUILTINS` shrinks to just the two `mock_*` ids by Task 5. Task 4 flags that the selectors' `evaluate` contract differs from the trigger algorithms' and requires the registry typing to be widened rather than the port distorted.
