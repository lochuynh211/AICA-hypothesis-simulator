透明ハイブリッド・トリガー v0.2（コンパクト9特徴量）

AICA 透明ハイブリッド・トリガー
アルゴリズム詳細解説

AICA（AI コックピット・アシスタント）が「危険運転になる前に休憩を提案する」ための判定ロジックを、 現行実装（aica_transparent_hybrid_trigger_v1 / v0.2）に基づいて、 設計理由とともに解説します。

一言で言うと： 眠気・疲労・運転の乱れ・環境負荷を 数式でスコア化し、 平滑化と継続判定でノイズを除き、 発火制御でしつこさを抑えながら、危険になる前に 実行可能な休憩・気分転換の提案を出すアルゴリズムです。

概要 ―「透明ハイブリッド」とは

このアルゴリズムの名前は、その設計思想をそのまま表しています。

「透明（Transparent）」

なぜ発火したか（あるいは、なぜ発火しなかったか）を必ず説明できるという意味です。 どの特徴量が・どの重みで・どのしきい値を超えたのか、その全過程がティックごとに記録され、 後から検証できます。ブラックボックス（説明できないAI）ではありません。

「ハイブリッド（Hybrid）」

単純な if 文（ルール）でも、統計モデル任せの一発判定でもなく、 複数の特徴量スコア・状態遷移・発火制御を組み合わせているという意味です。 「解釈できるルール」の分かりやすさと、「連続値スコア」のきめ細かさの両取りを狙っています。

なぜこの方式なのか

車載アシスタントは、判断根拠を人が監査・調整できることが極めて重要です。 「なんとなく休憩を勧めてきた」では、ドライバーも開発者も信頼できません。 透明ハイブリッドは、各ステップが数式として開かれているため、 セットアップ画面上で重みやしきい値を直接編集して挙動を確かめられます ―― 本資料はその画面に映る数式の「意味」と「理由」を言葉で補うものです。

3つの入力階層

特徴量の材料となる信号は、性質ごとに3つの階層に分かれています。 固定（夜間・慣れた道・子供同乗・悪天候など、走行前に決まる条件）、 実測（連続運転時間・区間種別・渋滞・次の休憩地点など、走行中に算出される値）、 シミュレート（眠気・疲労・異常発生率など、ドライバーモデルが生成する値）です。

2つの並列判定

このアルゴリズムは、性質の違う2つの問いを同時に・独立に評価しています。

なぜ2つに分けるのか

「疲れて危険」と「単調で退屈」は別の問題であり、適切な対応も違うからです。 前者は安全に直結するため休憩を、後者は快適性・覚醒維持のため気分転換を提案します。 別カテゴリにすることで、それぞれに独自のしきい値・クールダウン・優先度を設定でき、 同時に条件を満たしたときは安全（休憩）を必ず優先できます。

※ 以降、STEP 1〜6 は主に 休憩必要度 を例に説明します。単調性抑止度も まったく同じ仕組み（特徴量 → 平滑化 → スコア → 状態 → 継続 → 発火制御）で動きます。

19つの特徴量

センサー値や環境値は、そのまま判断に使いません。まず AICA が扱いやすい 0.0〜1.0 の特徴量に正規化します（clamp は 0〜1 に丸める関数）。 現行 v0.2 の特徴量は次の9つです。

眠気 ドライバー状態drowsiness
眠気信号 ÷ 100

シミュレートされた眠気（0–100）を正規化。危険運転防止で最重要の指標。

疲労 ドライバー状態fatigue
疲労信号 ÷ 100

長時間運転による蓄積疲労。眠気とは別に蓄積する。

運転異常度 ドライバー状態driving_anomaly
clamp( 異常発生率 ÷ K )

ハンドルのふらつき等、実際の運転の乱れの発生率。K（既定5）で正規化。実挙動としての危険兆候。

連続運転度 ドライバー状態driving_time
bins( 前回の休憩からの運転分 )
< 60分 → 0.0 60–120分 → 0.4 120–180分 → 0.7 ≥ 180分 → 1.0

連続運転時間による疲労リスク。生の分数ではなく段階（バンド）で扱う。

環境負荷 環境env_load
clamp( 0.5·( 渋滞? 1 : 渋滞時間(分)/20 ) + 0.3·高速時間(分)/60 + 0.2·悪天候/100 )

渋滞・長時間高速・悪天候など、運転を消耗させる外的負荷。休憩・単調の両スコアに効く。

単調度 環境monotony
clamp( 0.6·単調路時間(分)/30 + 0.4·夜間 )

単調な道が続く・夜間である、という覚醒低下の要因。単調性抑止度の主入力。

休憩タイミング 休憩ロジrest_window
bins( 次の休憩地点までの分 )
なし → 0.0 ≤ 3分 → 0.6 3–10分 → 1.0 10–20分 → 0.6 > 20分 → 0.2

3〜10分先が最高値。近すぎる（判断が間に合わない）・遠すぎる（今の提案に無関係）を避ける、非単調な形。

休憩の希少性 休憩ロジrest_scarcity
clamp( ( 次の休憩地点までの分 − 10 ) ÷ 50 )

次の休憩機会が遠いほど大きい＝「今を逃すと当分休めない」度合い。

慣れた道 文脈familiar_route
慣れた道? 1 : 0

通い慣れた道は緊張感が下がり単調になりやすい。単調性抑止度に加点。

なぜ「バンド化（段階分け）」するのか

連続運転度と休憩タイミングは、生の分数ではなく段階値に丸めています。これは本プロジェクトの 「定性的・境界ビン化トリガー原則」に基づくもので、理由は3つあります。 ① センサー誤差やわずかな数値変動で判断が揺れない（頑健性）。 ② 人間の感覚に近い（「127.3分運転した」ではなく「2時間を超えた」で考える）。 ③ 休憩タイミングのように、値の大小が単調でない関係（近すぎても遠すぎてもダメ）を素直に表現できる。

2平滑化（EWMA）

特徴量が一瞬だけ跳ね上がっても即発火しないよう、各特徴量に指数移動平均（EWMA）を掛けます。

平滑値[t] = α · 現在値[t] + ( 1 − α ) · 平滑値[t−1]   （α = smoothing_alpha, 既定 0.5）

例（α = 0.5）：前ティックの平滑化眠気が 0.40、今ティックの眠気が 0.80 のとき ―

平滑化眠気 = 0.5 × 0.80 + 0.5 × 0.40 = 0.60

現在値が急に上がっても、判断に使う値は段階的に上がります。α が大きいほど反応が速く、小さいほど安定します。

重要な順序

カテゴリスコア（次のSTEP）は、平滑化した後の特徴量から計算します。 つまり「スコアを平滑化する」のではなく「特徴量を平滑化してからスコアにする」順序です。 これにより、各特徴量のノイズが合成前に個別に均され、判断値に慣性が生まれます。

3カテゴリスコア

平滑化した特徴量から、重み付き合成で3つのスコアを計算します。重みはすべて編集可能なハイパーパラメータです。

① 基礎安全リスク base_safety_risk

危険運転につながる純粋なリスク（休憩地点情報は含まない）。

基礎安全リスク = clamp( 0.30·眠気 + 0.20·疲労 + 0.25·運転異常度 + 0.15·連続運転度 + 0.10·環境負荷 )
特徴量重み意味
眠気0.30危険運転防止で最重要
運転異常度0.25実際に現れている危険兆候
疲労0.20長時間運転の蓄積
連続運転度0.15休憩からの経過（段階値）
環境負荷0.10渋滞・高速・悪天候による消耗

重みの合計は 1.0。すべての特徴量が 0〜1 なので、基礎安全リスクも自然に 0〜1 に収まります。

② 休憩必要度 rest_required_score

基礎安全リスクに、休憩地点の都合を加味した最終スコア。ただし単純な加算ではありません。

休憩ボーナス = [ 基礎安全リスク ≥ 0.45 ] · ( 0.10·休憩タイミング + 0.08·休憩の希少性 )
休憩必要度 = clamp( 基礎安全リスク + 休憩ボーナス + [ 子供同乗 ] · 0.05 )
設計の核心 ―「リスクが IF を、休憩地点が WHEN を決める」

休憩ボーナスにはゲート条件があります：基礎安全リスクが 0.45 以上のときだけ加算されます。 これは「休憩施設が近いだけでは絶対に発火させない」という強い設計意図です。 疲労・眠気・運転異常が低ければ、たとえ休憩施設が目の前でも提案しません。 リスクが「休憩すべきか（IF）」を決め、休憩地点情報は「いつ提案するか（WHEN）」の微調整にのみ使う ―― 関心の分離です。

子供同乗ボーナス

子供が同乗しているときは 0.05 を加点し、やや早めに休憩を促します。 ただしこれはゲートの後に加算されるため、これ単独でゲートを開けることはできません ―― リスクが既にあるときに、タイミングを少し前倒しする「保守側の調整ダイヤル」です。

③ 単調性抑止度 monotony_prevention_score

単調性抑止度 = clamp( 0.40·単調度 + 0.30·環境負荷 + 0.20·慣れた道 )

単調な道・環境負荷・慣れた道が重なるほど高くなり、気分転換の提案候補になります。

4状態判定

休憩必要度に応じて、状態を段階化します（しきい値はすべて編集可能）。

REST_NORMAL< 0.5通常
REST_WATCH≥ 0.5内部監視（提案なし）
REST_SUGGEST≥ 0.7穏やかな休憩提案（gentle）提案候補
REST_RECOMMEND≥ 0.8明確な推奨（clear）
REST_URGENT≥ 0.9強い安全懸念（strong）

REST_SUGGEST（0.7）以上で初めて提案候補になります。休憩受諾後は REST_RECOVERY（再提案抑制）へ遷移します。 単調性抑止度も同様に MONOTONY_NORMAL → WATCH（0.5）→ CONTENT_SUGGEST（0.7） の段階を持ちます。

5継続判定とスキップ条件

候補（スコア ≥ 0.7）になっても、すぐには発火しません。既定では6ティック連続でしきい値を超える必要があります。

継続OK = ( 連続候補ティック数 ≥ 6 )  または  ( スコア > 0.9 )  または  ( 変化速度 > 0.2 )

変化速度 = 今ティックのスコア − 前ティックの平滑化スコア。 つまり、通常は「数ティック粘って本物と確認できてから」発火しますが、 スコアが極端に高い、または急上昇しているときは、粘りを待たずに即発火します。

なぜ「粘り」と「例外」の両方が要るのか

継続判定は、一瞬の crossing（しきい値をかすめる動き）を除くための忍耐です。 一方スキップ条件は、本当に急激で深刻な悪化を待たせないための安全弁です。 ふだんは慎重に、いざというときは即座に ―― この2面性が誤発火と手遅れの両方を防ぎます。

なぜクールダウン・上限・緊急例外がセットなのか

クールダウン（900秒）と30分上限（3回）は「しつこさ」を防ぐためです。 提案を連発するとドライバーは AICA を無視するようになり、本当に必要なときに効かなくなります。 しかし ―― 本物の危機（スコア 0.9 以上）だけは、これらの制限を飛び越えて発火します。 「うるさくしない」と「危険を見逃さない」を両立させる仕組みです。

優先順位と強度

優先順位：休憩必要度（1）＞ 単調性抑止度（2）。同順位ならスコアの高い方。
gentle（穏やか）：スコア ≥ 0.7 clear（明確）：スコア ≥ 0.8 strong（強い）：スコア ≥ 0.9

両カテゴリが同時に発火可能なとき、安全に直結する休憩提案が必ず選ばれます。

ステートフルな工夫

このトリガーはティックをまたいで状態を持ち越します（平滑化値・継続カウンタ・累積量・状態ラベル）。 中でも「休憩による回復」を正しく表すため、2つの重要な工夫があります。

① 休憩後のリベースライン

連続運転度は「前回の休憩からの経過分」で測ります。休憩を取ると基準がリセットされ、 休憩直後に連続運転度がほぼ 0 に戻ります ―― 休憩が実際にリスクを下げることを反映します。

② 走行中のみ進む環境・単調の累積

渋滞時間・高速時間・単調路時間は、走行中（MOVING）のときだけ加算されます。 さらに休憩でこれらもリベースされるため、休憩後は環境負荷・単調度も一度下がり、 走行再開後に再び蓄積します。「休憩は単調も和らげる」という直感に一致させています。

現行の既定パラメータで、実際に数値を入れて確かめます（平滑化後 ≒ 生値として概算）。
