# AICA 透明ハイブリッド・トリガー説明

## 対象

本資料は、`aica_trigger_condition_skeleton.png` の **①危険運転防止向け提案**、つまり **休憩が推奨される状態（疲れている / 今後疲労する）** に絞って説明します。

AICAは、単に「運転時間が長い」だけでは発火しません。  
ドライバー状態、車両挙動、道路環境、休憩可能性をtickごとに評価し、危険運転につながる前に休憩を提案します。

> 補足: アルゴリズム内部には、これと並列でもう1つの判定系列（**単調運転防止**：単調な道・慣れた道・注意力低下による気分転換提案）も動いています。本資料は①の休憩判定に絞って解説しますが、単調運転防止も**同じ仕組み（特徴量→平滑化→スコア→状態判定→継続判定→発火制御）** で動く点だけ覚えておいてください。

## 全体像

```text
シナリオ・道路・車両データ
→ tickごとに眠気/疲労/注意力をシミュレーション
→ 0.0-1.0の特徴量に変換
→ 平滑化して一瞬のノイズを抑制
→ 重み付きスコア（休憩必要度）を計算
→ 状態判定・継続判定
→ 発火制御
→ 休憩提案
```

この方式を「透明ハイブリッド」と呼びます。  
透明とは、どの特徴量・重み・しきい値で発火したかを説明できることです。  
ハイブリッドとは、単純なルールではなく、複数の特徴量スコア、状態遷移、発火制御を組み合わせていることです。

## 全体アルゴリズム（一気通貫の数式）

詳細は以降の各章で説明しますが、まず**休憩判定の全工程**を1か所にまとめます。  
各 tick `t`（30秒ごと）で、上から順に次を計算します（`clamp` は 0.0〜1.0 に丸める関数）。

```text
Δt = 30秒,  係数 = Δt / 60 = 0.5,  α = 0.35

# 1) 走行状態の更新
距離[t]         = 距離[t-1] + 速度 × Δt
連続運転時間[t] = 連続運転時間[t-1] + 0.5分

# 2) ドライバー状態の更新（増加量は「1分あたり係数 × 0.5」）
眠気[t]   = clamp( 眠気[t-1]   + (基本 + 夜間 + 単調路 + 渋滞) × 0.5 )
疲労[t]   = clamp( 疲労[t-1]   + (基本 + 60分超連続 + 山道 + 渋滞) × 0.5 )
注意力[t] = clamp( 注意力[t-1] + 自然回復 - 単調路低下 - 眠気低下 + 回復コンテンツ )

# 3) 特徴量への正規化（すべて 0.0〜1.0）
眠気f      = 眠気[t] / 100
疲労f      = 疲労[t] / 100
運転の乱れ = ハンドル不安定度 / 100
注意力低下 = 1 - 注意力[t] / 100
将来疲労   = clamp( 0.45×渋滞スコア + 0.35×長距離高速スコア + 0.20×悪天候スコア )
休憩タイミング     = f(次の休憩施設までの時間)        # 章「休憩タイミングの計算」参照
休憩機会の少なさ   = g(今後30分の休憩施設数)          # 同上

# 4) 平滑化（全特徴量に適用）
平滑[t] = α × 現在値[t] + (1 - α) × 平滑[t-1]

# 5) カテゴリスコア（平滑化済み特徴量から計算）
基礎安全リスク = clamp( 0.40×眠気f + 0.25×疲労f + 0.25×運転の乱れ + 0.10×将来疲労 )
休憩ボーナス   = (基礎安全リスク ≥ 0.45)
                 ? ( 0.10×休憩タイミング + 0.08×休憩機会の少なさ )
                 : 0
休憩必要度[t]  = clamp( 基礎安全リスク + 休憩ボーナス )

# 6) 変化速度と状態判定
変化速度 = 休憩必要度[t] - 休憩必要度[t-1]
状態 = REST_NORMAL    (0.45未満)
     | REST_WATCH     (0.45以上)
     | REST_SUGGEST   (0.58以上)   ← 提案候補
     | REST_RECOMMEND (0.76以上)
     | REST_URGENT    (0.88以上)

# 7) 継続判定
候補    = 休憩必要度 ≥ 0.58
継続OK  = (連続候補回数 ≥ 2)
          または 休憩必要度 > 0.88
          または 変化速度 > 0.08

# 8) 発火制御
発火 = 候補 かつ 継続OK かつ
       ( 休憩必要度 ≥ 0.88                               # 緊急: 以降の制限を無視
         または ( クールダウン外(600秒) かつ 30分提案数 < 3 ) )

# 9) 出力
発火なら → 強度（gentle/clear/strong）に応じた休憩提案を提示
```

以降の章は、この各ステップを順に詳しく説明します。

## 1 tickで何をしているか

パッケージは **30秒ごと** に評価されます。

各tickでは、まず走行状態を更新します。

```text
距離[t+1] = 距離[t] + 速度 × 30秒
連続運転時間[t+1] = 連続運転時間[t] + 0.5分
次の休憩施設までの時間 = 残距離 / 現在速度
```

次に、ドライバー状態を更新します。

```text
眠気[t+1] =
  眠気[t]
+ 基本増加
+ 夜間加算
+ 単調路加算
+ 渋滞加算

疲労[t+1] =
  疲労[t]
+ 基本増加
+ 60分以上連続運転の加算
+ 山道加算
+ 渋滞加算

注意力[t+1] =
  注意力[t]
+ 自然回復
- 単調路による低下
- 眠気による低下
+ 回復コンテンツによる回復
```

実装上は、各増加量は「1分あたりの係数 × tick時間」で計算します。

```text
tick係数 = tick秒数 / 60 = 30 / 60 = 0.5
```

例:

```text
夜間の眠気加算 = 夜間係数(1分あたり) × 0.5
渋滞中の疲労加算 = 渋滞係数(1分あたり) × 0.5
```

これにより、シナリオ再生中に眠気・疲労・注意力が少しずつ変化します。

## 監視データから特徴量へ

tickで生成された数値は、そのまま最終判断には使いません。  
まず、AICAが扱いやすい **特徴量（0.0〜1.0）** に変換します。

| 入力（センサー値） | 特徴量（日本語） | 内部キー | 変換 |
|---|---|---|---|
| 眠気レベル 0-100 | 眠気 | `drowsiness` | 眠気レベル / 100 |
| 疲労レベル 0-100 | 疲労 | `fatigue` | 疲労レベル / 100 |
| ハンドル不安定度 0-100 | 運転の乱れ | `driving_anomaly` | ハンドル不安定度 / 100 |
| 注意力レベル 0-100 | 注意力低下 | `attention_drop` | 1 - 注意力レベル / 100 |
| 渋滞・高速残時間・天候 | 将来疲労 | `future_fatigue` | 将来疲労要因として合成 |
| 次の休憩施設までの時間 | 休憩タイミング | `rest_window` | 休憩提案しやすいタイミング |
| 今後30分の休憩施設数 | 休憩機会の少なさ | `rest_scarcity` | 休憩機会の少なさ |

また、説明用にバンド化（段階分け）も行います。

```text
眠気:
0-19   なし   (none)
20-39  弱     (weak)
40-59  中     (moderate)
60-79  強     (strong)
80-100 重度   (severe)

疲労:
0-29   低     (low)
30-59  中     (medium)
60-100 高     (high)
```

## 将来疲労の計算

「今はまだ疲れていないが、この先疲労しやすい」状態も見ます。

```text
渋滞スコア =
  0.0  渋滞なし
  0.3  10分未満
  0.6  10-30分
  1.0  30分以上
（低速走行が続く場合は、その継続時間による値とのうち高い方を採用）

長距離高速スコア =
  0.0  10分未満
  0.3  10-30分
  0.6  30-60分
  1.0  60分以上

悪天候スコア = 悪天候レベル / 100
```

将来疲労は次の式で計算します。

```text
将来疲労 =
  0.45 × 渋滞スコア
+ 0.35 × 長距離高速スコア
+ 0.20 × 悪天候スコア
```

つまり、渋滞が長い、長時間高速が続く、悪天候であるほど、将来疲労リスクが上がります。

## 休憩タイミングの計算

休憩施設が「近すぎる」「遠すぎる」場合は、提案として使いにくくなります。

```text
休憩タイミング =
  0.0  休憩施設なし
  0.6  3分以内
  1.0  3-10分
  0.6  10-20分
  0.2  20分超
```

3-10分先を最も高くしています。  
理由は、ドライバーが判断して車線変更・減速・立ち寄りを行いやすいからです。

休憩機会の少なさも見ます。

```text
休憩機会の少なさ =
  1.0  この先30分に休憩施設なし
  0.7  1件
  0.4  2件
  0.1  3件以上
```

## スコア式

### 1. 基礎安全リスク

まず、危険運転につながる基礎リスクを計算します。

```text
基礎安全リスク =
  0.40 × 眠気
+ 0.25 × 疲労
+ 0.25 × 運転の乱れ
+ 0.10 × 将来疲労
```

重みの意味:

| 特徴量 | 重み | 意味 |
|---|---:|---|
| 眠気 | 0.40 | 危険運転防止では最重要 |
| 疲労 | 0.25 | 長時間運転の蓄積を反映 |
| 運転の乱れ | 0.25 | 実際の危険兆候を反映 |
| 将来疲労 | 0.10 | この先悪化しそうな状況を反映 |

### 2. 休憩推奨スコア（休憩必要度）

休憩施設が近いだけでは発火させません。  
まず基礎安全リスクが一定以上であることを確認します。

```text
もし 基礎安全リスク < 0.45 なら:
    休憩ボーナス = 0
そうでなければ:
    休憩ボーナス =
      0.10 × 休憩タイミング
    + 0.08 × 休憩機会の少なさ
```

最終的な休憩推奨スコア（休憩必要度）は以下です。

```text
休憩必要度 = 基礎安全リスク + 休憩ボーナス
```

ポイント:

- 疲労・眠気・運転異常が低い場合、休憩施設が近くても提案しない
- リスクが一定以上なら、「今休めるか」「この先休みにくいか」を加点する
- 休憩提案は安全リスクが主、休憩施設情報はタイミング調整

## 平滑化

センサー値やシナリオ値が一瞬だけ上がっても、すぐ発火しないように平滑化します。

```text
平滑化済み特徴量[t] =
  α × 現在の特徴量[t]
+ (1 - α) × 平滑化済み特徴量[t-1]
```

既定値:

```text
α = 0.35
```

例:

```text
前tickの平滑化済み眠気 = 0.40
現在tickの眠気 = 0.70

平滑化済み眠気 =
  0.35 × 0.70 + 0.65 × 0.40
= 0.505
```

現在値が急に上がっても、判断値は段階的に上がります。

なお、カテゴリスコア（基礎安全リスク・休憩必要度）は、**平滑化した後の特徴量** から計算します。

## 状態判定

休憩必要度に応じて、状態を段階化します。

| 状態 | しきい値 | 意味 |
|---|---:|---|
| `REST_NORMAL` | 0.45未満 | 通常 |
| `REST_WATCH` | 0.45以上 | 内部監視 |
| `REST_SUGGEST` | 0.58以上 | 休憩提案候補 |
| `REST_RECOMMEND` | 0.76以上 | 明確な休憩推奨 |
| `REST_URGENT` | 0.88以上 | 強い安全懸念 |
| `REST_RECOVERY` | 休憩受諾後 | 再提案抑制 |

`REST_SUGGEST`以上になると、休憩提案の候補になります。

## 継続判定

候補になっても、すぐには発火しません。  
休憩提案では、既定で **2 tick連続** してしきい値を超える必要があります。

```text
tick秒数 = 30秒
休憩持続ティック数 = 2

必要な継続時間 = 30秒 × 2 = 60秒
```

ただし、以下のような急な悪化は例外です。

```text
休憩必要度 > 0.88
または
スコア変化速度 > 0.08
```

この場合は、継続判定を待たずに提案できます。

```text
スコア変化速度 =
  休憩必要度[t]
- 休憩必要度[t-1]
```

## 発火制御

提案しすぎを防ぐため、候補が成立しても最終発火前に制御します。

```text
1. 候補がなければ発火しない
2. 緊急レベルなら制限を超えて発火可能
3. 直前提案からのクールダウン中なら抑制
4. 30分あたりの提案上限を超えていれば抑制
5. すべて通れば発火
```

既定値:

```text
休憩提案クールダウン = 600秒（10分）
30分あたり最大提案数 = 3
緊急オーバーライドしきい値 = 0.88
```

## 具体例

### 発火する例

```text
眠気             = 0.70
疲労             = 0.65
運転の乱れ       = 0.40
将来疲労         = 0.60
休憩タイミング   = 1.00
休憩機会の少なさ = 0.40
```

基礎安全リスク:

```text
基礎安全リスク =
  0.40×0.70
+ 0.25×0.65
+ 0.25×0.40
+ 0.10×0.60
= 0.6025
```

`0.45`以上なので休憩ボーナスを加算します。

```text
休憩ボーナス =
  0.10×1.00
+ 0.08×0.40
= 0.132

休憩必要度 = 0.6025 + 0.132 = 0.7345
```

このスコアが平滑化後も2 tick続くと、`REST_SUGGEST`として休憩提案候補になります。  
`0.76`に近いため、状況によっては明確な休憩推奨へ進みます。

### 発火しない例

```text
眠気             = 0.10
疲労             = 0.20
運転の乱れ       = 0.00
将来疲労         = 0.20
休憩タイミング   = 1.00
休憩機会の少なさ = 1.00
```

```text
基礎安全リスク =
  0.40×0.10
+ 0.25×0.20
+ 0.25×0.00
+ 0.10×0.20
= 0.11
```

基礎安全リスクが`0.45`未満なので、休憩施設が近くても休憩ボーナスは付きません。

```text
休憩必要度 = 0.11
→ 提案しない
```

## AICAから見た説明文

発火時には、単に「休憩してください」ではなく、根拠を追跡できます。

```text
休憩必要度がしきい値を超え、一定時間継続しました。
主な根拠:
- 眠気
- 疲労
- 運転の乱れ
- この先の疲労要因
- 休憩施設までの時間
```

提案文の例:

```text
疲労のサインが続いています。早めの休憩をお勧めします。
```

より強い状態では:

```text
安全のため、直ちに休憩を取ってください。
```

## 顧客向けの要点

- 眠気・疲労・運転異常・将来疲労を重み付きで評価する
- tickごとに眠気/疲労/注意力をシミュレーションし、状態が時間とともに変わる
- 休憩施設情報は「発火理由」ではなく「提案タイミング」の補正に使う
- 平滑化と継続判定により、一瞬のノイズでは発火しない
- クールダウンと回数制限により、提案しすぎを防ぐ
- ただし高リスク時は安全優先で緊急発火できる

## 一言で言うと

AICAの透明ハイブリッド・トリガーは、  
**眠気・疲労・運転の乱れ・この先の疲労要因を数式でスコア化し、tickごとの状態変化と発火制御を通して、危険運転になる前に実行可能な休憩提案を出すアルゴリズム** です。
