1. What this algorithm decides1. このアルゴリズムが決めること

It answers one question: among the services already allowed for the current purpose and lifecycle stage, which services best fit the current situation and configured customer hypothesis?

答える問いは1つです。 現在の発火目的とライフサイクル段階で既に許可されたサービスの中で、現在状況とお客様が設定した仮説に最も合うサービスはどれかを判断します。

≤ 3

Ranked services順位付きサービス

The result contains up to three eligible service candidates.

利用可能なサービス候補を最大3件返します。

17

Baseline featuresベースライン特徴量

Every candidate is evaluated using the same complete feature contract.

全候補を同じ完全な特徴量契約で評価します。

[-1,+1]

Normalized service fit正規化サービス適合度

Zero is neutral; positive supports the candidate; negative opposes it.

0は中立、正は候補を支持、負は候補に反対する方向です。

Safety and eligibility happen first. Motion state, screen restrictions, service availability, lifecycle rules, and catalog requirements remove impermissible candidates before ranking. No feature weight or high fit can restore an excluded service.

安全性と利用可否を先に判定します。 走行状態、画面制約、サービス提供可否、ライフサイクル規則、カタログ要件により、許可できない候補を順位付け前に除外します。どれほど重みや適合度が高くても、除外サービスは復活しません。

4Calculate service fit適合度を計算
5Rank up to three最大3件を順位付け

2. One transparent calculation2. 透明な計算の流れ

The model is a deterministic weighted sum. There are no hidden bands, random choices, learned probabilities, or LLM judgments.

このモデルは決定論的な加重和です。隠れたバンド、乱数、学習済み確率、LLMによる判断はありません。

The complete formulation完全な計算式の構成

xᵢ(c)Raw input生入力
eᵢ(c)Normalized evidence正規化エビデンス
aᵢ(c)Candidate response coefficient候補反応係数
rᵢ(c)Normalized feature response正規化特徴量反応
wᵢ(p)Effective weight有効重み
kᵢ(c)Feature contribution特徴量寄与度
F(c)Service fitサービス適合度
eᵢ(c) = Nᵢ(xᵢ(c))
aᵢ(c) = response_profile[c][i]
rᵢ(c) = clamp(eᵢ(c) × aᵢ(c), -1, +1)
Bᵢ = category_weight × subgroup_weight × leaf_weight
qᵢ(p) = Bᵢ × purpose_multiplier[p][subgroup(i)]
wᵢ(p) = qᵢ(p) ÷ Σⱼqⱼ(p)
kᵢ(c) = wᵢ(p) × rᵢ(c)
service_fit(c) = F(c) = clamp(Σᵢkᵢ(c), -1, +1)

4. Weights express importance4. 重みは重要度を表す

This section calculates the effective normalized weight wᵢ(p) for every feature. A weight says how much that feature may influence the result for purpose p; it does not say whether a candidate is suitable.

このセクションでは、各特徴量の有効正規化重みwᵢ(p)を計算します。重みは目的pにおいてその特徴量が結果へ与えられる影響の大きさを表し、候補が適合するかどうかは表しません。

OUTPUT: wᵢ(p) The weight calculation uses the configured hierarchy and trigger purpose. For one proposal opportunity, the resulting 17 weights are shared by every service candidate.

出力：wᵢ(p) 設定された重み階層と発火目的から計算します。1回の提案機会では、計算された17個の重みをすべてのサービス候補で共通利用します。

Situation 0.80状況 0.80
Preference .12嗜好 .12
History .08履歴 .08

Step 1 — base feature weight Bᵢ手順1 — 特徴量の基本重み Bᵢ

Bᵢ = Ccategory × Ssubgroup × Lleaf

C is a top-level category ratio, S a subgroup ratio inside that category, and L a leaf ratio inside that subgroup. For drowsiness:

Cは最上位カテゴリ比率、Sはカテゴリ内サブグループ比率、Lはサブグループ内の個別特徴量比率です。眠気の場合：

Bdrowsiness = 0.80 × 0.50 × 0.55 = 0.22

Sibling values are ratios that sum to 1 at each level.

各階層の同階層値は合計1になる比率です。

Steps 2–3 — purpose adjustment and normalization手順2〜3 — 目的調整と正規化

qᵢ(p) = Bᵢ × Msubgroup(p)
Z(p) = Σⱼ qⱼ(p)
wᵢ(p) = qᵢ(p) ÷ Z(p)

M emphasizes a subgroup for trigger purpose p. q is an intermediate adjusted weight, Z is the sum across all 17 features, and w is the final weight used in service fit.

Mは発火目的pに応じてサブグループを強調します。qは調整途中の重み、Zは17特徴量すべてのqの合計、wがサービス適合度で使用する最終重みです。

Complete drowsiness-weight calculation for inattentive-driving prevention漫然運転予防における眠気重みの完全な計算

B = 0.80 × 0.50 × 0.55 = 0.22
q = B × M = 0.22 × 1.50 = 0.33
Z = Σ q across 17 features = 1.2964
wdrowsiness(inattentive) = 0.33 ÷ 1.2964 = 0.254551

The result 0.254551 is not yet a candidate score. It is later multiplied by that candidate's normalized feature response r_drowsiness(c) to calculate contribution k_drowsiness(c).

結果の0.254551は、まだ候補のスコアではありません。後で候補別の正規化特徴量反応r_drowsiness(c)と掛け、寄与度k_drowsiness(c)を計算します。

Initial purpose multipliers Msubgroup(p)初期目的別倍率 Msubgroup(p)

Each cell is an intermediate multiplier M, not the final weight. Select the column matching purpose p, apply its values to the 17 base weights, and normalize them together to obtain wᵢ(p).

各セルは途中で使用する倍率Mであり、最終重みではありません。目的pに一致する列を選び、17個の基本重みに適用した後、それらをまとめて正規化するとwᵢ(p)になります。

Weight and response are different. Weight asks “how important is this feature now?” Response asks “does this particular service suit the evidence?” Both are visible and customer-editable hypotheses.

重みと反応は別物です。 重みは「今この特徴量がどれほど重要か」、反応は「このサービスがそのエビデンスに合うか」を表します。どちらも可視化され、お客様が調整できる仮説です。

6. Worked example: humming karaoke6. 計算例：鼻歌カラオケ

Purpose: inattentive-driving prevention / recovery. Candidate: humming karaoke. The example uses the initial effective weights for that purpose.

目的：漫然運転予防・回復。候補：鼻歌カラオケ。この例では同目的の初期有効重みを使用します。

How service_fit is calculated for every candidate: hold the purpose and its 17 weights fixed, select one candidate c, then loop through all 17 features. In each loop, calculate or retrieve x → e → a → r → k. Sum that candidate's 17 values of k to obtain service_fit(c). Repeat the same loop for the next candidate; only candidate-specific evidence and response coefficients may change.

7. What customers can tune and evaluate7. お客様が調整・評価できること

Recommended tuning order推奨調整順序

  1. Confirm eligibility and candidate constraints.利用可否と候補制約を確認する。
  2. Review candidate-response meanings.候補反応の意味を確認する。
  3. Tune category and subgroup weights.カテゴリとサブグループ重みを調整する。
  4. Tune purpose multipliers and leaf weights.目的別倍率と個別重みを調整する。
  5. Tune curves or ordinal mappings only with a product reason.製品上の理由がある場合のみ曲線・順序尺度を調整する。

Best evaluation method最適な評価方法

Clone one complete scenario, change only one feature or hyperparameter, recompute, and compare effective weights, contributions, reasons, and rank movement.

完全なシナリオを複製し、特徴量またはハイパーパラメータを1つだけ変えて再計算し、有効重み、寄与度、理由、順位変化を比較します。

  • Not clinical or safety certification医学的・安全認証ではない
  • Not permission to bypass eligibility利用可否を迂回する許可ではない
