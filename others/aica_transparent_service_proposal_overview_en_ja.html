1. What this algorithm decides1. このアルゴリズムが決めること

It answers one question: among the services already allowed for the current purpose and lifecycle stage, which services best fit the current situation and configured customer hypothesis?

答える問いは1つです。 現在の発火目的とライフサイクル段階で既に許可されたサービスの中で、現在状況とお客様が設定した仮説に最も合うサービスはどれかを判断します。

≤ 3

Ranked services順位付きサービス

The result contains up to three eligible service candidates.

利用可能なサービス候補を最大3件返します。

17

Baseline featuresベースライン特徴量

Every candidate is evaluated using the same complete feature contract.

全候補を同じ完全な特徴量契約で評価します。

[-1,+1]

Normalized service fit正規化サービス適合度

Zero is neutral; positive supports the candidate; negative opposes it.

0は中立、正は候補を支持、負は候補に反対する方向です。

Safety and eligibility happen first. Motion state, screen restrictions, service availability, lifecycle rules, and catalog requirements remove impermissible candidates before ranking. No feature weight or high fit can restore an excluded service.

安全性と利用可否を先に判定します。 走行状態、画面制約、サービス提供可否、ライフサイクル規則、カタログ要件により、許可できない候補を順位付け前に除外します。どれほど重みや適合度が高くても、除外サービスは復活しません。

1Purpose and stage目的・段階
2Hard eligibility必須の利用可否
3Evaluate 17 features17特徴量を評価
4Calculate service fit適合度を計算
5Rank up to three最大3件を順位付け

2. One transparent calculation2. 透明な計算の流れ

The model is a deterministic weighted sum. There are no hidden bands, random choices, learned probabilities, or LLM judgments.

このモデルは決定論的な加重和です。隠れたバンド、乱数、学習済み確率、LLMによる判断はありません。

1Normalize raw feature生特徴量を正規化
2Resolve service responseサービス反応を決定
3Feature response特徴量反応を計算
4Apply effective weight有効重みを適用
5Sum service fit適合度を合計

Feature response特徴量反応

rᵢ(c) = evidenceᵢ(c) × response_coefficientᵢ(c)

Evidence says what is happening. The response coefficient says whether candidate c is suitable for that evidence.

evidenceは「何が起きているか」、response coefficientは候補cがその状況に合うかを表します。

Contribution and service fit寄与度とサービス適合度

kᵢ(c) = wᵢ × rᵢ(c)
service_fit(c) = Σ kᵢ(c)

Every contribution is visible and the contributions add directly to the final fit.

各寄与度はすべて表示でき、その合計が最終適合度になります。

All scoring values stay normalizedスコアに関係する値はすべて正規化

-1
Strongest opposition最も強い反対
0
Neutral中立
+1
Strongest support最も強い支持

Raw values may use natural units. Drowsiness 80 is normalized to 0.80 before scoring. A rate such as 75% acceptance becomes +0.50 because 50% is defined as neutral. Endpoints are valid, so ranges use inclusive brackets.

生値は元の単位を保持できます。 眠気80は計算前に0.80へ正規化します。一方、採用率75%は50%を中立とするため+0.50になります。端点も有効なので範囲は角括弧で示します。

4. Weights express importance4. 重みは重要度を表す

The default hierarchy makes current situation dominant while still allowing personalization and synthetic history to influence the order.

初期階層では現在状況を支配的にしつつ、個人嗜好と合成履歴も順位に影響できるようにします。

Situation 0.80状況 0.80
Preference .12嗜好 .12
History .08履歴 .08

Hierarchy example: drowsiness階層例：眠気

0.80 Situation × 0.50 Driver state × 0.55 Drowsiness = 0.22

Sibling values are normalized ratios. Customers can start at category level, then refine subgroups and leaves.

同階層の値は正規化される比率です。お客様はカテゴリから始め、サブグループ、個別特徴量の順に細かく調整できます。

Purpose multiplier目的別倍率

effective_raw_weight = base_weight × purpose_multiplier

調整後の17重みを再正規化し、合計を1にします。ライフサイクル段階は候補を変えますが、重みセットは変えません。

Weight and response are different. Weight asks “how important is this feature now?” Response asks “does this particular service suit the evidence?” Both are visible and customer-editable hypotheses.

7. What customers can tune and evaluate7. お客様が調整・評価できること

Recommended tuning order推奨調整順序

  1. Confirm eligibility and candidate constraints.利用可否と候補制約を確認する。
  2. Review candidate-response meanings.候補反応の意味を確認する。
  3. Tune category and subgroup weights.カテゴリとサブグループ重みを調整する。
  4. Tune purpose multipliers and leaf weights.目的別倍率と個別重みを調整する。
  5. Tune curves or ordinal mappings only with a product reason.製品上の理由がある場合のみ曲線・順序尺度を調整する。

Best evaluation method最適な評価方法

Clone one complete scenario, change only one feature or hyperparameter, recompute, and compare effective weights, contributions, reasons, and rank movement.

完全なシナリオを複製し、特徴量またはハイパーパラメータを1つだけ変えて再計算し、有効重み、寄与度、理由、順位変化を比較します。

Warnings do not silently change results警告は結果を自動変更しない

Examples: safety-context share below 40%, an unusually high multiplier, too much missing evidence, or a response contradicting source-explicit intent. The edited hypothesis remains visible and evaluable.

例：安全文脈比率が40%未満、異常に高い倍率、欠損エビデンス過多、資料で明示された意図と矛盾する反応。編集した仮説は可視化されたまま評価できます。

What service fit does not meanサービス適合度が意味しないこと

  • Not acceptance probability採用確率ではない
  • Not measured recovery effectiveness実測された回復効果ではない
  • Not clinical or safety certification医学的・安全認証ではない
  • Not permission to bypass eligibility利用可否を迂回する許可ではない

Evidence retained for every decision各判断で保存するエビデンス

raw_value normalized_evidence response_coefficient normalized_feature_response effective_weight feature_contribution provenance service_fit

Missing baseline evidence is neutral and disclosed. Invalid values block evaluation. Identical inputs and configuration reproduce the same ranking, using candidate ID only to break an exact numerical tie.

欠損したベースラインエビデンスは中立として明示します。不正値は評価を停止します。同じ入力と設定から同じ順位を再現し、数値が完全に同点の場合のみ候補IDで順序を決めます。
