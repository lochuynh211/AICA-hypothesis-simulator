AICA 透明サービス提案アルゴリズム — CDC-SU ベースライン V1AICA transparent service-proposal algorithm — CDC-SU baseline V1

一言で言うと：発火（提案の機会）が決まったあとで、どのサービスを、どの順番で提案するかを決めます。各特徴量について、evidence（状況の強さ）e_i に、応答係数 a_i（候補サービスがどれだけ応えられるかを表す値 — スライド67をもとに人手で決めた値）を掛け合わせます。これを重みの階層で重み付けして合計し、service_fit ∈ [-1,+1] を求め、上位3件を返します。service_fit は受諾確率でも、回復効果でも、安全性を保証する値でもありません。 In one line: after the trigger has established a proposal opportunity, this ranks which services to propose. Each feature multiplies evidence e_i (how strongly the context calls for something) by a response coefficient a_i (how well the candidate service answers it — a hand-authored value derived from Slide 67), weighted by the feature hierarchy and summed into service_fit ∈ [-1,+1]. Returns the top three. service_fit is not an acceptance probability, a recovery effect, or a safety certification.

1概要 ― 考え方Overview — the idea

すべての特徴量は同じ形をしています。evidence（状況の強さ）e_i（いまの世界がどれだけ強いか）に、応答係数 a_i（その候補がどれだけ応えられるか）を掛け合わせます。evidence は、その時点の世界のスナップショットから1回だけ読み取ります。係数のほうは候補サービスIDごとに決まる固定の値で、スライド67とサービス定義（スライド38–40）から決めます。各特徴量の r_i = e_i·a_i に重みを掛けて足し合わせます。絶対的な安全性は採点の前に行うハード適格性が受け持ち、相対的な適合度は目に見えて編集もできる重みと係数で表します。 Every feature takes the same shape: an evidence value e_i (how strong the current world is) times a response coefficient a_i (how well this candidate answers it). Evidence is read once from the world snapshot; the coefficient is a stable property of the candidate service ID, derived from Slide 67 and the service definitions (Slides 38–40). Each feature's r_i = e_i·a_i is scaled by its hierarchical weight and summed. Absolute safety lives in hard eligibility (before scoring); relative suitability lives in visible, editable weights and coefficients.

範囲は構造で保証（隠れclampなし）Bounds hold by construction (no hidden clamp)

各係数は |a_i| ≤ 1、evidence は [-1,+1] の範囲なので、r_i ∈ [-1,+1] になります。重みは0以上で合計1なので、Σ k_i ∈ [-1,+1] です。最後の clamp は浮動小数点の誤差を吸収するためだけのもので、不正な入力によって範囲をはみ出した値を隠すためのものではありません。 Each coefficient satisfies |a_i| ≤ 1, evidence is in [-1,+1], so r_i ∈ [-1,+1]. Weights are non-negative and sum to one, so Σ k_i ∈ [-1,+1]. The final clamp guards only floating-point drift — it must never conceal an out-of-range value from invalid input.

「実効重み」とは（3行で）What “effective weight” means (three lines)

base_weight_i   = category_weight × subgroup_weight × leaf_weight
raw_weight_i(p) = base_weight_i × purpose_multiplier[p][subgroup]
w_i(p)       = raw_weight_i(p) / Σ_j raw_weight_j(p)

目的が変わると重みは変わりますが、候補の応答プロファイルはライフサイクル段階が変わっても同じです（§3）。ライフサイクル段階が選ぶのは別の重みセットではなく、候補ファミリーだけです。数値の扱いはこうなっています：IEEE-754 binary64、17特徴量の順序は固定、NaN・±∞は拒否、順位付けはフル精度で行い丸めは表示のときだけ、−0は+0として扱う、完全に同点のときは candidate_id の昇順、許容誤差は 1e-12。 Purpose changes weights, but a candidate's response profile is stage-independent (§3). Stage selects the family, not another weight set. Numeric rules: IEEE-754 binary64; fixed 17-feature order; reject NaN/±inf; full-precision ranking, round only for display; −0→+0; exact ties by candidate_id ascending; tolerance 1e-12.

3レスポンス係数 — どう決めるかResponse coefficients — how they are set

応答係数が答える問いはシンプルです。「このevidenceがあるとき、この候補サービスは適切に応えるか、中立か、それとも矛盾するか」。ドライバーのデータから学習した値ではありません。既定値は5段階のおおまかなアンカーから選びますが、パラメータの記録も下の表も、クラス名のようなコードではなく数値そのものを保持します。 The coefficient answers: “when this evidence is present, does this candidate service respond appropriately, remain neutral, or conflict?” It is not learned from driver data. Defaults come from a coarse five-value anchor set — but the parameter record and every table below store the number directly, not a class code.

係数を決める3つの規則The three derivation rules

1 · 1候補IDにつき1プロファイルOne profile per candidate ID

サービスの応答は候補IDごとに決まる固定の値で、発火目的やライフサイクル段階が変わっても変化しません。発火目的が変えるのは重みだけ（マルチプライヤ、§6）で、段階が選ぶのは適格なファミリーだけです。だから休憩前①と走行中②–④の走行系サービスは、1つのマトリクスを共有します。A service's response is a stable property of the ID; it does not change with purpose or stage. Purpose changes only weights (§6); stage only selects the family. So before-rest ① and active-driving ②–④ share one driving matrix.

2 · 方向はスライド67、大きさは出典の強さDirection from Slide 67, magnitude from source strength

スライド67が名指しで「優先」としているサービスは +1.0。できないことはないが名指しされていないサービスは、弱めの +0.5。無関係なら 0.0。マイナスになるのは、正規化した文脈での安全上の推論（山道など）のときだけです。A service Slide 67 names as preferred → +1.0; plausibly capable but unnamed → mild +0.5; irrelevant → 0.0. Negatives only from normalized-context safety reasoning (mountain).

3 · 沈黙は中立、負ではないSilence is neutral, not negative

スライド67が優先サービスを挙げていない場合（例えば目的①のドライバー／環境の列は「ー」）は、根拠のはっきりした仮説がない限り 0.0（neutral_source_silent）とします。Where Slide 67 lists no preferred service (e.g. the ① driver/environment column is ー), the coefficient is 0.0 (neutral_source_silent) unless a labeled hypothesis justifies otherwise.

4レスポンス・マトリクス（実係数）The response matrices (real coefficients)

ここがアルゴリズムの核心です。各特徴量がどんな証拠を読み取り、各候補サービスがどう応えるか。ライフサイクル・ファミリーごとに3つのマトリクスがあり、各セルは数値の係数 a_i(c) です。 The heart of the algorithm: what evidence each feature reads, and how each candidate service answers. Three matrices, one per lifecycle family. Every cell is the numeric coefficient a_i(c).

+1.0 強く支持strongly supports +0.5 支持supports 0.0 中立neutral −0.5 反対opposes −1.0 強く反対strongly opposes — 停車で環境リセットreset by stopped snapshot

1つの規則：evidence × responseOne rule: evidence × response

r_i(c) = clamp( e_i(c) · a_i(c), −1, +1 )     |  道路種別のみroad type only: e=1 → r = a_road(c)

evidence には2つの形があります。片方向の e ∈ [0,1]（0はエビデンスなしという意味で、マイナス方向という意味ではありません：眠気・疲労・単調さ・渋滞・夜間・ルート・目的地・子供・グループ・推し登録・新規性）。両方向の e ∈ [-1,+1]（0は中立という意味：推しモード・全体/場面別の利用度・受諾率・回復率）。 Evidence has two shapes. One-directional e ∈ [0,1] (0 = no evidence, not evidence against: drowsiness, fatigue, monotony, traffic, night, route, destination, child, group, oshi-registered, recency). Two-directional e ∈ [-1,+1] (0 = neutral: oshi-mode, overall/scene usage, acceptance, recovery).

なぜ4つの活性化サービスは眠気/疲労で同じ +1.0 なのかWhy the four activation services share +1.0 on drowsy/fatigue

スライド67は眠気と疲労度を1つの行にまとめ、4つのサービス（鼻歌/合いの手/クイズ/ランキング）を、優劣もつけず眠気と疲労の区別もせずに名指ししています。だからサービスの層では同じ優先度になり、同じ係数にすることが出典に忠実な扱いです。とはいえ、この4つがまったく区別されないわけではありません。ルート/目的地（音楽・鼻歌だけが対象）、山道（相互作用の負荷）、候補ごとの好み・履歴では、ちゃんと差がつきます。「眠気なら元気づけ、疲労なら和らげる」といった細かい区別はコンテンツ選択の仕事です。そこでは arousal（覚醒度）/valence（快度）による曲の応答として表現されます（眠気は +0.80·A_s、疲労は −0.50·A_s）。 Slide 67 puts drowsiness and fatigue in a single row and names the same four services with no ranking and no drowsy-vs-fatigue split — so at the service level they are equally preferred, and a uniform coefficient is source-faithful. The four are not indistinguishable overall: they separate on route/destination (only music/humming), on mountain road (interaction load), and on per-candidate preference/history. The finer “energize a drowsy driver, soothe a fatigued one” distinction is the content selector's job — expressed there as the arousal/valence song response (drowsiness +0.80·A_s, fatigue −0.50·A_s), not as a service choice.

Motion is a platform eligibility fact, not a ranking feature. Excluded services get no service_fit and are reported with reason codes — the algorithm may not reinstate them.

欠損・不明・不正データMissing, unknown, and invalid data

  • 欠損（値そのものがない、または候補マップに項目がない）→ e=0, r=0, k=0とし、重みはそのまま残してmissing_neutralとします。欠損があっても重みを他に振り分けたり、プラスにもマイナスにもエビデンスをでっち上げたりはしません。Missing → e=0, r=0, k=0, weight retained, missing_neutral. Absence never redistributes weight or invents evidence.
  • 生の値が0（[0,100]の特徴量）は有効な低い値であって、欠損ではありません。不明なタグは認識数のカウントには入れず、記録だけします。Raw 0 on a [0,100] feature is a valid low value. Unknown tags don't contribute to the count and are reported.
  • 停車時のスナップショット：during_rest_stoppedでは、渋滞→normal、道路→parking、単調さ→0にします（眠気/疲労/昼夜はそのときの値のまま）。after_rest_before_restartでは、休憩後として明示された眠気/疲労の値を使い、環境は同じ停車状態のままです。ルート/目的地・同乗者は、そのときの旅程の事実をそのまま使います。停車する前の渋滞/道路/単調さの値を、暗黙のうちに引きずらないようにしてください。Stopped snapshot: during_rest_stopped sets traffic→normal, road→parking, monotony→0 (drowsiness/fatigue/day-night stay current); after_rest_before_restart uses explicit post-rest drowsiness/fatigue with the same stopped environment. Route/destination and passengers stay current. Never implicitly retain pre-stop congestion/road/monotony.
  • 不正な入力（型が違う、範囲外、対応していないenum、矛盾する推し状態、有限でない数値、兄弟グループが全部ゼロ、実効重みの分母がゼロ）→ 型付きのエラーで処理を止めます。黙って中立の値にすり替えることは決してありません。Invalid (wrong type, out-of-range, unsupported enum, contradictory oshi state, non-finite, all-zero sibling group, zero active-weight denominator) → blocks with a typed error; never silently coerced to neutral.

対比テスト（一部）Contrast tests (selected)

カタログ・発火目的・設定・シードを固定したまま、1つの変数だけを変えて、並び順がちゃんと変わるかを確認します：眠気/疲労/単調さの低↔高、通常↔渋滞、高速↔山道、昼↔夜、子供の有無、推しモードのoff/on、サービス新規性、全体利用度、回復率、route_music↔inattentive（ルート/目的地の重みが動いて音楽↔鼻歌が入れ替わる）、山道↔高速（相互作用の多いクイズ/ランキングが山道で下がる）。適格な候補は必ずすべて順位付けされ（スコアが低くても除外されません）、ハード除外されたものが復活することもありません。 Freeze catalog/purpose/config/seed, change one field, assert the reorder: low↔high drowsiness/fatigue/monotony; normal↔congested; highway↔mountain; day↔night; child absent↔present; oshi mode off↔on; service recency; overall usage; recovery; route_music vs inattentive (route/destination weight shift reorders music vs humming); mountain vs highway (interaction-heavy quiz/ranking drop on mountain). Every eligible candidate is always ranked (never suppressed by a low score); a hard exclusion is never reinstated.

9設計判断と保留Design choices & deferred

radio の解決（スライド39 vs 70）radio_style resolution

スライド70はコンテンツ層の話なので、サービスの係数には影響しません。スライド39がradioを推しサービスと定義しているので、推しの特徴量は+1.0（他は0.0）です。使えるかどうかは、さらに「新しい推し情報がある」というフラグで適格性の面からもゲートします。Slide 70 is content-level and doesn't drive service coefficients. Slide 39 defines radio as the oshi service, so oshi = +1.0 (else 0.0). Availability is additionally gated by a “new oshi info” eligibility flag.

一様な活性化係数Uniform activation coefficients

スライド67は眠気と疲労を1つの行で扱い、優劣をつけずに4つのサービスを名指ししているので、サービス層では一律に+1.0とするのが出典に忠実です。細かい区別は、コンテンツ選択のarousal/valence（覚醒度/快度）が受け持ちます。Slide 67 puts drowsiness+fatigue in one row and names four services without ranking, so a uniform +1.0 is source-faithful; the finer distinction is the content selector's arousal/valence job.

結果・エラー区分Result & error categories

ranked_candidates · no_proposal · invalid_request · invalid_catalog · invalid_configuration。型付きのエラーには根拠となる情報が付いていて、宣言されていないフォールバック・サービスを出したり、順位をでっち上げたりすることはありません。 Typed errors carry evidence and never produce an undeclared fallback service or a fabricated ranking.

保留（別パッケージ）Deferred

確率的な不確実性ランキング（重みや係数の設定範囲からサンプリングして、期待fit・fitの区間・1位になる確率を報告するもの — これは順位の安定性を表すのであって、受諾/回復の確率ではありません）。それから、候補ごとの推しメンバー/グループのグラフや、信頼度で重み付けした疎な履歴も保留にしています。A probabilistic uncertainty-ranking package (samples ranges around weights/coefficients to report expected fit, a fit interval, and probability of ranking first — rank stability, not acceptance/recovery probability). Also per-service oshi member/group graphs and confidence-weighted sparse history.
