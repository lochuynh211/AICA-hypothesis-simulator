① 休憩スポットをどう用意するか— UC（ルート）ごとの事前準備

1 / 2
休憩スポットは、走行中にその場で探しているわけではありません。UC（ルート）ごとに事前に一度だけ Google Maps から抽出し、その結果をプリセットとして JSON に保存しています（実行時はAPI キーもネット接続も不要）。「プリセット」と「地図からの検索」は並列に選べる 2 つの方法ではなく、下の STEP 1 → 2 → 3 で検索した結果がプリセット、という関係です。
STEP 1ルートを確定するDirections API
  • UC ごとに 出発地・目的地・高速道路を使うか否か（avoid=highways）を指定し、Google Directions API から実際のルート（線形＋案内ステップ列）を取得します。
  • 現在 8 本のルートを用意済みです。例：東京駅→大阪駅（高速・501.8km）、東京駅→軽井沢（一般道・159.9km）、みなとみらい→小田原（57.1km／その半高速版）、名古屋→犬山（27.5km／その全一般道版）、船橋→幕張（6.9km）。
  • 取得したルートを、案内ステップ単位で 高速道路（HIGHWAY）／一般道（LOCAL）に判定します。判定材料は次の 3 つです。
    • 案内文に highway / expressway / toll 等を含むか
    • そのステップの長さ（長い直進区間は高速道路とみなす保険）
    • 合流・ランプ（merge / ramp）かどうか。ただし案内文に国道・県道など一般道の名称が入る場合は一般道と判定します。
この道路種別の判定が、STEP 2 の「どこで・何を検索するか」をすべて決めます。
STEP 2ルート上を検索するPlaces API v1
  • 検索地点の置き方：同じ道路種別が続く区間を n 等分し、各区画の中央に 1 点ずつ置きます（n = 区間長 ÷ 8km の四捨五入、最低 1 点／全体で上限 80 点）。
  • 置いた各中央点から、その周囲を検索して休憩スポットを見つけます。1 点につき 2 回、半径 5km の円で検索します（下表が実際の引数です）。
  • 点の置き方・半径・除外条件は高速／一般道で共通で、種別によって変わるのは検索内容（下表）だけです。
地点の道路種別検索内容と引数
高速道路 Text Search 「サービスエリア」／「パーキングエリア」を各 1 回
languageCode=ja, maxResultCount=20, locationBias=円(半径5,000m)
一般道 Text Search 「道の駅」（maxResultCount=20）＋ Nearby Search コンビニ（includedTypes=["convenience_store"], maxResultCount=5）
languageCode=ja, locationRestriction=円(半径5,000m)
STEP 3絞り込んで保存するプリセット JSON
  • 検索結果をそのまま使うと、実際には立ち寄れない施設が混ざります。そこで次の順に除外します。
    • 高速地点で拾えた「道の駅」を除外（道の駅は一般道側の施設で、高速走行中は降りられないため）
    • 重複排除：Places の id が同一なら同じ施設。id が無い場合は名称＋位置（1.5km 以内）で同一とみなします。
    • 反対車線の SA/PA を除外：施設名の「上り／下り」表記と、進行方向に対する左右から、走行中の車線側かを判定します。道の駅・コンビニには上下線の概念が無いため、この判定は行いません。
    • ルートから 2km 以上離れた施設を除外（検索は半径 5km の円なので、直線距離では近くてもルートからは大きく外れる施設が混ざるため）
  • 残った施設を自分と同じ道路種別のルート上の点にだけ投影し、「起点から何 km 地点か」を確定させます（同じ種別の点が近くに無い施設は破棄）。この km 値が、②の選定でそのまま使われます。
  • コンビニは一般道の点でしか検索せず、一般道の点にしか投影されません。そのため高速区間にコンビニが並ぶことはありません（プリセット実データでも、高速区間に載ったコンビニは 0 件）。
  • 最後に km 順に並べ、施設名・緯度経度とともに JSON に保存します。
下段はこの除外をすべて通過した最終件数です。件数は指定しておらず、「ルート上を漏れなく探し、立ち寄れないものを落とした結果」がこの数になります。

② トリガー発火時に、どのスポットを提案するか— ①で用意したリストから、いまの位置を基準に最大 5 件へ

2 / 2
1
リストを読み込む
①で保存したこのルートの休憩スポット全件を候補にします。施設名と、起点から何 km 地点かを持っています。
プリセットを使わないシナリオでは施設名が無いため、「Rest stop 1、2 …」の汎用名になります。

2
前方だけを残す
「先」の判定は、各スポットの「起点からの累積距離」と、車の「現在までの累積走行距離」を比べて行います（地図上の直線距離ではなく、ルートに沿った距離）。スポット > 現在地 + 1.0kmこの 1.0km は、短距離のテスト走行に合わせた設定値です。
→
3
近い順に並べる
残った候補を起点からの km 昇順（＝現在地から近い順）に並べます。
以降の処理はすべてこの順序を前提にしているため、同じ条件なら結果は毎回同じになります。
→
4
間隔をあけて 5 件
先頭から順に採用し、直前に採用したスポットから 2.0km 未満のものは飛ばします。5 件に達した時点で終了です。
単純な「近い順に 5 件」ではなく、互いに 2km 以上離れた 5 件が選ばれます。
→
5
到着時の眠気を確認
絞り込んだ各候補について、到着時の眠気を予測します。到着予定時間 = 距離 ÷ 現在速度 × 60分到着時の眠気 = 現在の眠気
　　　+ 眠気増加率(/分) × 到着予定時間上限以下なら選択可、超えたらグレーアウトして選択不可。全件が上限超過の場合は、最も近い 1 件だけ選択可に戻します。
未実装提案するスポットは、いま走っている「ルート上」のものだけです。ルートを外れた場所（そこへ向かうにはルートの引き直しが必要な休憩所）を提案する機能は、まだ入っていません。そのため提案は常に、いまの道の先にある休憩所の中から選ばれます。
